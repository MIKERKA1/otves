# «Отвес»: исследование, концепция, архитектура

Демо-проект для портфолио. Компания вымышленная, заявки никуда не отправляются.

## 1. Инструменты и источники

### Что используется

| Инструмент | Статус | Как используется |
|---|---|---|
| Playwright CLI (`@playwright/cli` 0.1.22) | devDependency | ручная проверка страниц и скриншоты |
| Playwright Test + `@axe-core/playwright` | devDependency | автотесты, проверка доступности |
| Anime.js 4.5 | dependency | рисование линий SVG, разбивка заголовков, счётчики, таймлайны |
| Motion 14 (vanilla) | dependency | реакции интерфейса: панели, диалоги, шаги помощника, `inView` |
| Phosphor Icons core | dependency | иконки SVG на этапе сборки, без рантайма |

### Библиотеки компонентов: что взяли и от чего отказались

Kokonut UI, Magic UI, React Bits, Aceternity UI, 21st.dev, RetroUI и Origin UI построены на React + Tailwind + shadcn. Проект собран без React: страницы почти целиком статичные, а интерактивные блоки небольшие. React добавил бы около 45 КБ gzip ради нескольких виджетов. Визуальный язык этих библиотек (стеклянные карточки, свечения, «бенто») прямо противоречит ТЗ. Поэтому код компонентов не копировался, взяты только паттерны поведения:

- сравнение «до/после» (Aceternity Compare) сделано на нативном `input type=range`, чтобы оно управлялось с клавиатуры без ARIA-обвязки;
- разбивка заголовка на слова (React Bits SplitText) сделана через `splitText` из Anime.js;
- плавная смена числа (Magic UI Number Ticker) сделана анимацией объекта в Anime.js.

OriginKit оказался закрытым сервисом с инвайтами и лимитом скачиваний, а не открытым репозиторием. Bklit UI это графики для дашбордов, здесь графиков нет. tweakcn генерирует темы для shadcn, токены здесь написаны вручную на CSS-переменных.

### Что видно на сайтах ремонтных компаний

Русские сайты: квизы со «скидкой за ответы», калькуляторы с одной цифрой, «гарантия до 5 лет» без условий, обещания «фиксированной сметы» без объяснения механики. Зарубежные (Block Renovation, Sweeten): оценка бюджета диапазоном, этапы с конкретными людьми, оплата по факту выполненных этапов, фото проектов с площадью, сроком и составом работ.

Выводы для «Отвеса»:

1. Цена показывается диапазоном, с явной пометкой, что это ориентир, и с объяснением, что меняет итог.
2. Доверие строится на механике договора (как фиксируется цена, как принимаются скрытые работы), а не на счётчиках клиентов.
3. Человеку без строительного опыта нужен вход «опишите проблему», а не каталог услуг.
4. Портфолио показывает процесс, а не только глянец «после».

## 2. Концепция

**Название:** «Отвес». Это грузик на нитке, которым проверяют вертикаль. Инструмент, который не врёт.
**Слоган:** «Делаем ровно».
**Позиционирование:** ремонт, потолки, окна, сантехника и электрика одной командой: одна смета, один договор, один прораб на связи.

**Идея визуального языка:** чертёж и стройка. Чертёж объясняет (план квартиры, разрез монтажного шва, график работ), фотография доказывает (реальный ремонт по этапам, от кирпича до плитки). Главный смелый элемент один: интерактивный план квартиры на первом экране. Остальное сдержанное.

### Токены

| Роль | Светлая | Тёмная | Откуда |
|---|---|---|---|
| Фон «штукатурка» | `#EEF0EC` | `#15181B` | холодный гипс, не кремовый |
| Поверхность «свежая краска» | `#F9FAF7` | `#1D2226` | |
| Текст «графит» | `#1D2125` | `#E9ECE7` | строительный карандаш |
| Вторичный текст | `#4B535A` | `#A3ABA5` | |
| Линии «бетон» | `#C7CCC6` | `#343B40` | |
| Сигнальный жёлтый | `#F0C23B` | `#F2C744` | корпус рулетки; только заливки с графитовым текстом |
| Успех «уровень» | `#2F6B4F` | `#5DB48A` | |
| Ошибка | `#B42318` | `#F97066` | |

Кремовый фон с терракотой, неон на чёрном, фиолетовые градиенты и стекло не используются.

**Шрифт:** Geologica Variable, один на всё. Ось `SHRP` (острота) включается в заголовках и даёт им «отрезанные» углы, как у трафарета. Тело текста без остроты. Свой хостинг через Fontsource, без Google Fonts.

**Форма:** радиус 4 px у полей и кнопок, 10 px у фото и панелей. Тени почти не используются: уровни задаются фоном.

**Движение:** одна сцена при загрузке (план рисуется линиями, заголовок поднимается по словам). Всё остальное отвечает на действия человека. При `prefers-reduced-motion` всё сразу на месте.

## 3. Структура и UX

Главная собрана вокруг вопросов клиента, а не вокруг типового порядка секций:

| Вопрос клиента | Блок | Что в нём особенного |
|---|---|---|
| Кто это и что делают? | Первый экран | план квартиры: зоны работ кликаются и ведут к услугам |
| Можно ли им доверять в принципе? | Полоса обещаний | четыре условия, каждое проверяемо в договоре |
| Что нужно сделать? | Услуги | у каждой услуги свой интерактив: уровни ремонта, фактуры потолка, слои монтажного шва, прайс сантехника, уровни работ электрика |
| Не знаю, что мне нужно | Помощник | проблема → симптом → мастер, срок, цена, что подготовить → заявка с готовым описанием |
| Сколько стоит? | Калькулятор | диапазон, состав, что не входит, передача расчёта в заявку |
| Как это выглядит? | До/после и кейсы | реальные фото по этапам, кейсы помечены как демо |
| Как всё пройдёт? | График работ | диаграмма этапов для трёх сценариев: окна, ванная, квартира |
| Что меня защищает? | Договор | пункты договора с пояснениями простыми словами |
| Остались вопросы | FAQ | нативные `<details>` |
| Что делать дальше? | Заявка | минимум полей, согласие, понятная судьба данных |

Страницы услуг (`/uslugi/<id>/`) отвечают на сценарий «мне нужно заменить окна»: что делаем, варианты, этапы, цены, что подготовить, вопросы, форма с уже выбранной услугой.

Мобильная версия проектируется отдельно: план уменьшается, а услуги под ним становятся крупными кнопками. После первого экрана появляется нижняя панель «Позвонить / Оставить заявку», которая прячется у формы и пока открыт баннер cookie.

## 4. Приватность и данные

Принцип: сайт не собирает то, что не нужно функции. Функции «отправить заявку настоящей компании» у демо нет, поэтому заявка не уходит никуда.

| Данные | Где живут | Зачем | Сколько хранятся | Как удалить |
|---|---|---|---|---|
| Поля заявки и фото | память открытой вкладки | показать, что получила бы компания | до очистки формы или закрытия вкладки | кнопка «Очистить заявку», закрытие вкладки |
| `otves.consent` | localStorage | помнить выбор по cookie | 12 месяцев, потом вопрос задаётся снова | страница «Ваши данные», ссылка «Настройки cookie» |
| `otves.theme` | localStorage | помнить тему, если её выбрали вручную | пока не сброшена | страница «Ваши данные» |
| `otves.stats` | localStorage, только с согласия | анонимные счётчики: просмотры страниц и использование калькулятора, помощника и формы | 30 дней, затем обнуляется; при отзыве согласия удаляется сразу | страница «Ваши данные» |

Cookie сайт не ставит вообще. Сторонних запросов нет: шрифты, фото и скрипты отдаются с того же домена. Модуль статистики грузится отдельным файлом только после согласия. Если задать `PUBLIC_STATS_ENDPOINT`, он будет отправлять туда те же обезличенные события через `sendBeacon`. Без этой переменной данные остаются в браузере, и их можно посмотреть на странице «Ваши данные».

Фото из формы проверяются по сигнатуре файла (JPEG, PNG, WebP), размеру до 10 МБ и количеству до трёх. Перед «отправкой» они перекодируются через canvas, и это удаляет метаданные, включая геолокацию.

## 5. Архитектура

- Astro 7, статическая сборка, TypeScript strict, без UI-фреймворка.
- Переключение панелей сделано на радиокнопках и `:has()`, поэтому работает без JS. JS добавляет анимацию и расчёты.
- Встроенный CSP Astro (meta-тег с хешами), `public/_headers` для хостингов с поддержкой заголовков.
- Нативные переходы между страницами через `@view-transition`.
- Данные (услуги, цены, помощник, кейсы, FAQ) лежат в `src/data/` и отделены от разметки. Формулы калькулятора чистые и покрыты тестом на `node:test`.
